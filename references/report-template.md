# Структура итогового отчёта (Фазы 5–6)

## Фаза 5: обязательные разделы синтеза

Финальный документ — не пересказ статистики, а цепочки
«Решение → Почему принято → Последствие → Цена → Кто мог остановить и когда → Что менять».

1. **Цепочки провалов** (12–20+): ложная готовность («тесты зелёные» → отбраковка
   по скриншотам), автономные марафоны без чекпоинтов, конфликты трактовки, выход за
   scope, тихое ослабление критериев приёмки, повторные баги между сессиями, побеги
   плейтестов, побеги-вызванные-фиксом, отклонённые пункты ревью.
2. **Вклад владельца** — конструктивно: какие формулировки/тайминги приёмки включали
   ошибки, пары «было → стало», практики владельца, которые работают.
3. **Неоптимальности процесса** — повторяющиеся дорогие циклы с оценкой цены каждого.
4. **Карта приёмки** — какой класс дефектов кто ДОЛЖЕН ловить (агент/ревью-сабагент/
   автотест/владелец) vs кто реально ловил.
5. **Топ-10 самых дорогих паттернов** — ранжировано по совокупной цене.
6. **Что менять** — готовые формулировки правил, шаблоны запросов владельца,
   изменения порядка работ; каждая правка привязана к классу провалов.

### Раунд независимой критики (обязателен)

Второй субагент холодной проверкой ищет: безыдоказательные заявления, пересказ вместо
причин, пропущенные паттерны, искажения источников (сверка с дайджестами и
`data/stats.json`). Автор дорабатывает документ до принятия; при расхождении мнений
факт проверяется по первоисточнику, а не «по памяти».

## Фаза 6: сборка `<OUT>/report.md`

Порядок разделов:

1. Методика и источники (какие хранилища, период, полнота покрытия по инструментам).
2. Общая статистика: таблицы по инструментам, таймлайн, паттерны запросов (из
   `stats.json`, `user_patterns.json`; графики при наличии).
3. Затыки и систематика (ретраи, кластеры ошибок инструментов).
4. Качественные разборы по эпохам: выжимки + ссылки на полные отчёты субагентов
   (`data/qual_*.md`, сохранённые дословно).
5. Паттерны взаимодействия (вмешательства, стиринг, стили).
6. Ошибки: что ловится / что не ловится (escaped defects, Фаза 4).
7. Выводы и рекомендации (из Фазы 5, разделы 1–6).
8. Приложения: пути данных, скрипты, графики, оговорки — метод подсчёта ошибок по
   каждому инструменту, список инструментов без cost-данных (`cost_untracked_tools`),
   дата среза.

Язык отчёта — язык владельца. Отчёт НЕ коммитить без решения владельца.

## Веб-страница итогов (report.html)

После report.md собери `<OUT>/report.html` скриптом
`python scripts/make_report_page.py --out <OUT>`. Скрипт сам тянет из `data/stats.json`
и `data/user_patterns.json`: KPI, таймлайн сессий по дням/инструментам, таблицу
инструментов, retry-топ, классификацию запросов, авто-оговорки (cost_untracked,
wall-часы, синтетика). Качественные находки передаются через
`data/report_highlights.json`, который ты заполняешь по итогам Фаз 3–5 (все поля
необязательны; полный формат — в docstring скрипта):

```json
{
  "title": "Название проекта", "subtitle": "стек · суть", "period": "dd.mm—dd.mm.yyyy",
  "repo": "C:\\путь\\к\\репо",
  "intro": "2–3 предложения нарратива",
  "tool_notes": {"codex": "эпоха/роль инструмента"},
  "stuck_loops": [["×19", "write_stdin-поллинг рендеров"]],
  "owner_quotes": [["дата · тема", "цитата с контекстом"]],
  "owner_notes": "абзац о паттернах взаимодействия",
  "defect_waves": [["MP2-1\n30.09", 3]],
  "repeat_escapes": ["self-model: MP2-steam → MP3"],
  "blind_spots": "абзац о слепых зонах",
  "conclusions": ["<b>жирное начало</b> → цена → рекомендация"],
  "extra_caveats": ["особые оговорки этого аудита"]
}
```

`repo` показывается в заголовке секции «Общая картина». Тексты highlights пиши на языке
владельца; хром страницы (подписи осей, заголовки секций) — русский. `conclusions`
допускает HTML-теги (`<b>`), остальное экранируется.
